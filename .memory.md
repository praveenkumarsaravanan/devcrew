# Project Memory

Accumulated learnings across development sessions. Entries are appended
automatically after each `team-workflow` completion and can be added
manually at any time.

## Architecture Decisions

### [2026-04-24] — Pure Markdown primitives over runtime framework
**Domain:** architecture
**Context:** Designing how DevCrew distributes AI team capabilities.
**Learning:** Every primitive (agents, skills, instructions, prompts, hooks) is a Markdown file — no runtime, no SDK, no compiled binary.
**Rationale:** Markdown is LLMs' native format. Any developer can read/modify files. APM compiles one source to Cursor, Copilot, and Claude Code targets.

### [2026-04-24] — Three-tier APM distribution model
**Domain:** architecture
**Context:** Needed standards to compose without conflict across org levels.
**Learning:** Tier 1 (DevCrew universal) → Tier 2 (team/org packages in `teams/` monorepo or separate repos) → Tier 3 (project-level `.project-context.md`, `.memory.md`). Lower tiers override higher ones.
**Rationale:** Teams customize DevCrew without forking. Project-specific config stays in the project repo.

### [2026-04-24] — Three-tier memory architecture with size budgets
**Domain:** architecture
**Context:** Persistent memory across sessions must stay within context window limits.
**Learning:** Tier 1 (`.memory.md`, ~150 lines, loaded every Phase 0) → Tier 2 (`.memory/<domain>.md`, loaded on keyword match) → Tier 3 (`.memory/archive/<quarter>.md`, loaded only on explicit request).
**Rationale:** Active context stays concise. Domain overflow prevents information loss. Quarterly archival preserves history without bloating.

### [2026-04-24] — PROSE specification alignment
**Domain:** architecture
**Context:** Needed a principled design framework for AI-native development.
**Learning:** Adopted PROSE — Progressive Disclosure (right-sizing), Reduced Scope (single-responsibility agents), Orchestrated Composition (team-workflow), Safety Boundaries (governance), Explicit Hierarchy (three-tier distribution).
**Rationale:** Provides a coherent design language that maps directly to DevCrew's features.

### [2026-04-27] — Evaluation framework with standard ML metrics
**Domain:** architecture
**Context:** Needed rigorous measurement of DevCrew's effectiveness beyond subjective rubrics.
**Learning:** Added Accuracy, Precision, Recall, F1, MAE, AUC-ROC mapped to 5 behavioral dimensions + skill output quality. Capability Levels (CL-1 through CL-6) gate what DevCrew can reliably do. Regression Levels (RL-0 through RL-4) detect degradation between releases.
**Rationale:** Standard metrics enable cross-release comparison, CI gating, and objective quality tracking.

## Auth & Security

### [2026-04-24] — Governance scales with risk level
**Domain:** auth-security
**Context:** Not every code change needs the same oversight — trivial tasks shouldn't block on human approval.
**Learning:** Three risk levels: LOW (full autonomy), MEDIUM (agent implements, human reviews PR), HIGH (agent proposes, human approves each step). Critical failures (SQL injection approved, auth modified without approval) trigger automatic zero scores.
**Rationale:** Prevents both extremes: agents aren't blocked on trivial tasks, and they can't autonomously modify authentication logic.

## Deployment

### [2026-04-25] — APM v0.9.2 self-deployment for local packages
**Domain:** deployment
**Context:** `apm install` in v0.8.11 did not deploy local `.apm/` content to `.cursor/`. Upgrading to v0.9.2 fixed it.
**Learning:** APM v0.9.2 introduced `<project root> (local)` self-deployment. `apm install --target cursor` now correctly deploys rules, agents, skills, and hooks to `.cursor/` directories.
**Rationale:** Eliminates the need for manual `apm compile` + copy workflows during local development.

### [2026-04-25] — APM does not deploy prompts to .cursor/commands/
**Domain:** deployment
**Context:** After upgrading APM, `.cursor/commands/` remained empty despite `apm.yml` having `prompts: .cursor/commands/`.
**Learning:** APM's Cursor integration does not natively map `.prompt.md` files to any target directory. Created `scripts/post-install.sh` as a workaround to copy prompts manually.
**Rationale:** Until APM adds native prompt deployment, the script bridges the gap. It supports both project-level and global installs.

### [2026-04-25] — APM scripts are manual, not automatic lifecycle hooks
**Domain:** deployment
**Context:** Expected `postinstall` to run automatically after `apm install`, like npm.
**Learning:** APM `scripts` are manual — must be invoked via `apm run <name>`. They are not automatic lifecycle hooks.
**Rationale:** Consumers need explicit documentation or alternative integration patterns.

## Testing

### [2026-04-27] — Subagent isolation prevents eval answer leakage
**Domain:** testing
**Context:** Running quality gate evals in the same session that reads the fixture's planted bug list biases results.
**Learning:** Spawn separate subagents for each eval run. Pass only the task description, not prior results or expected values. Read expected values only after execution for scoring.
**Rationale:** Mirrors DevCrew's production behavior (review phases run in isolated subagents) and prevents the judge from confirming its own answers.

### [2026-04-27] — Fixture-based testing for quality gates
**Domain:** testing
**Context:** Needed objective, repeatable inputs for code review evaluation.
**Learning:** Created `AuthService.java` (6 planted security bugs) and `PaymentForm.tsx` (5 planted bugs) as fixtures. Each bug has a known severity (CRITICAL/HIGH/MEDIUM/LOW) enabling Precision/Recall/F1 computation.
**Rationale:** Planted bugs with known ground truth make review quality measurable instead of subjective.

## General

### [2026-04-25] — Hybrid bootstrap: scripts create, AI enriches
**Domain:** general
**Context:** Debated whether to use shell scripts or AI agents for `.project-context.md` / `.memory.md` creation.
**Learning:** Shell scripts (`init-context.sh`, `init-memory.sh`) create minimal file structure with interactive prompts. The AI agent enriches content during Phase 0 with detected values.
**Rationale:** Scripts work without AI (CI, non-interactive). AI adds intelligence (auto-detecting stack, filling in architecture). Neither approach alone covers all scenarios.
